Operational Onboarding Process

From sales agreement to merchant go-live — Jordan (Onboarding Manager) is involved from the initial call onwards, coordinating with the Systems Department to ensure a seamless integration across all platforms and delivery services the merchant uses.

1
Sales Process
Sales Representative
Close agreement with the client.
  • Confirm delivery coverage (e.g. 2-mile radius), pricing: bike rate, catering/car rate, and special conditions.
  • Confirm which delivery channels the client currently uses: Uber Eats, DoorDash, Grubhub, Website, etc.
  • Confirm whether the client is currently using another logistics company for deliveries.
2
Initial Onboarding Call
Onboarding Team Jordan
Schedule and conduct the initial onboarding call with the client.
  • Confirm the exact delivery channels the client will give to Motoclick.
  • Define if the merchant uses a POS system: Toast, Square, Revel, or another.
  • Confirm if the merchant uses middleware to centralize orders: Chowly, Stream, KitchenHub, or other.
Jordan joins from this step to begin assessing integration complexity and pre-coordinate with the Systems Department — ensuring no disruption to existing platforms or delivery services the merchant already has in place.
3
Ecosystem Review
Onboarding Team Jordan Technical Support
Map the client's full operational ecosystem before any technical setup begins.
  • Identify the source of truth for orders: POS, middleware, delivery app dashboard, website, or email.
  • Confirm if existing integrations could be affected by the Motoclick onboarding process.
4
Integration Strategy
Onboarding Team Jordan
Define the best integration option based on the client's ecosystem.
  • Available options: KitchenHub, Email Protocol, Stream, Chowly, Direct API, or POS integration.
  • Select the option that allows Motoclick to receive orders without interrupting the merchant's current kitchen flow.
5
Implementation Request
Onboarding Team Jordan
Send the implementation request to the Systems Department via Notion, email, or WhatsApp.
  • Must include: client name, channels, POS, middleware, delivery radius, rates, and selected integration method.
  • Include all credentials, access details, or contact points needed for implementation.
6
Technical Implementation
Jordan Systems Department
Create the Motoclick Merchant Panel and configure the full integration.
  • Configure merchant account, delivery settings, and operational rules.
  • Synchronize the Merchant Panel with the selected integration: Email Protocol, KitchenHub, Stream, Chowly, API, or POS.
7
Testing Phase
Jordan Onboarding Team
Run a test order for each channel connected to Motoclick.
  • Verify orders flow correctly into Motoclick.
  • Verify POS printing, auto-acceptance, order data, pickup time, customer address, and dispatch synchronization.
  • Document issues and resolve them before handoff.
8
Operations Handoff & Go-Live
Operations Team
Notify Operations once all channel tests are approved.
  • Operations trains the client on how to use the Motoclick Merchant Panel.
  • Explain the 'Order Ready' workflow and when orders are released to dispatch.
  • Approve the merchant for go-live.

Alternative Method — Send the link to the restaurant owner

If you don't have the delivery provider credentials, you can send a unique link to the merchant so they can enter their own details. Once they complete the form, the provider is automatically integrated through Kitchenhub.

  1. In Kitchenhub, select the Provider you want to connect (e.g. Grubhub, UberEats, DoorDash).
  2. Kitchenhub will generate a unique connection URL. Copy it and send it to the restaurant owner.
    Example: https://khrestaurant.com/de93487689284cdeb1b1d1b817a881c8
  3. The merchant opens the link and fills in the three required fields:
    • Login — email or username for their provider account.
    • Password — password for that account.
    • Merchant ID — the restaurant's unique identifier on the provider.
  4. To find the Grubhub Merchant ID, look up the restaurant on grubhub.com and take the digits at the end of its page URL.
    Example: grubhub.com/restaurant/alvo-pizza-.../11614448 → Merchant ID: 11614448

Getting the Merchant ID from Sigma (Chowly's Platform)

To associate a restaurant with Motoclick's dispatch panel and start displaying their orders, you must obtain the Merchant ID from Sigma — Chowly's internal management platform. This ID is the unique identifier that links the merchant's delivery activity to our system.

  1. Log in to the Sigma platform using your Chowly admin credentials.
  2. Search for the restaurant by name or location.
  3. Open the merchant's profile and locate the Merchant ID field — this is the value you need.
  4. Copy the Merchant ID and enter it in Motoclick's panel to complete the association. Once linked, orders from this merchant will appear in the dispatch view.

The image below shows the Sigma platform. The Merchant ID is a required field — without it, Motoclick cannot route or display the merchant's delivery orders.

Setting Up the Restaurant's Google Email & Two-Factor Authentication

To enable email order scraping for the restaurant, we need to create a dedicated Google email account for them and enable Two-Factor Authentication (2FA). This is a required step before generating the App Password that Motoclick's Systems Department will use.

  1. Create the email account and navigate to the Google Account security settings to enable Two-Factor Authentication. The screen below shows the 2FA setup page:
  2. Once 2FA is enabled, your account security page will confirm it is active — as shown below:
  3. With 2FA active, go to Google Account → Security → App Passwords to generate the app password that will be shared with Motoclick's Systems Department. The App Passwords section looks like this:
  4. Google will generate a 16-character code (for example: ehqh ffqc wgru pgps). Copy this code and share it with Motoclick's Systems Department. This code allows Motoclick to scrape email orders from the restaurant's inbox on their behalf.
